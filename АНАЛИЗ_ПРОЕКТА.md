## АРХИТЕКТУРА TRINITY STATE

### Концепция
Проект реализует паттерн **Trinity State** - трехуровневую модель состояния персонажа:

```
┌─────────────────┐     assemble()     ┌─────────────────┐
│  DraftCharacter │ ─────────────────► │ CharacterSnapshot│
│   (Blueprint)   │                    │   (Projection)   │
└─────────────────┘                    └─────────────────┘
        │                                      │
        │                                      │
        ▼                                      ▼
┌─────────────────┐                    ┌─────────────────┐
│    levelStack   │                    │ CharacterLiveState│
│  (История выборов)│                  │   (Runtime State) │
└─────────────────┘                    └─────────────────┘
```

### 1. DraftCharacter (Blueprint Layer)
**Файл:** `domain/model/DraftCharacter.kt` (330 строк)

**Назначение:** Неизменяемый чертеж персонажа - полная история всех выборов.

**Ключевые компоненты:**
- `BaseInfo` - базовые характеристики (раса, класс, статы, background)
- `LevelStack` - история левел-апов с выборами (List<LevelStep>)
- `ChoiceResult` - sealed class для результатов выбора (Spells, Skills, StatBonus, etc.)

**Ключевые методы:**
```kotlin
fun getAllProficienciesWithLevels(): Map<String, Int>
fun getAllLearnedSpells(): Set<String>
fun getHistoricalLearnedSpells(untilLevelIndex: Int): Set<String>
fun resolveEffectiveStats(): Map<String, Int>
```

### 2. CharacterLiveState (Runtime Layer)
**Файл:** `domain/model/snapshot/CharacterLiveState.kt` (66 строк)

**Назначение:** Мутируемое состояние живого персонажа в игре.

**Ключевые компоненты:**
- `hpCurrent`, `hpTemp`, `transformationHp` - HP tracking
- `featureCharges` - использование ресурсов (Map<String, Int>)
- `equippedItemIds`, `attunedItemIds` - экипировка
- `preparedSpellIds` - подготовленные заклинания
- `concentrationSpellId` - концентрация
- `activeEffects`, `activeConditions` - активные эффекты
- `deathSaves` - спасброски от смерти
- `systemLogs` - лог операций

### 3. CharacterSnapshot (Projection Layer)
**Файл:** `domain/model/snapshot/CharacterSnapshot.kt` (221 строк)

**Назначение:** Вычисленная проекция персонажа для отображения.

**Ключевые компоненты:**
- `GlobalInfo` - имя, классы, уровни, lore
- `stats`, `skills` - финальные характеристики
- `features` - все фичи с описаниями
- `magic: MagicalRegistrySnapshot` - магическая система
- `combatActions` - боевые действия
- `inventory` - инвентарь
- `resourcePools` - пулы ресурсов
- `transformationMonster` - Wild Shape форма

## СИСТЕМА АССЕМБЛЕРОВ

### SnapshotAssembler (Main Orchestrator)
**Файл:** `domain/usecase/snapshot/SnapshotAssembler.kt` (420 строк)

**Архитектура:**
```
SnapshotAssembler
├── CoreStatAssembler         → StatRegistry
├── SkillRegistryAssembler    → List<SkillModel>
├── FeatureRegistryAssembler  → FeatureResult
├── VitalsAssembler           → VitalsResult (HP, HD, Speed)
├── MagicRegistryAssembler    → MagicalRegistrySnapshot
├── ResourceRegistryAssembler → List<ResourcePoolSnapshot>
├── AresAssembler             → List<CombatAction>
├── InventoryReconciler       → InventoryReconcileResult
└── TransformationApplier     → Transformed Stats/Skills
```

**Ключевой метод:**
```kotlin
suspend operator fun invoke(
    draft: DraftCharacter,
    oldSnapshot: CharacterSnapshot?,
    oldLiveState: CharacterLiveState?,
    entityCurrentHp: Int?,
    unpackedInventory: List<UnpackedItem>
): Pair<CharacterSnapshot, CharacterLiveState>
```

### AresAssembler (Combat System)
**Файл:** `domain/usecase/snapshot/AresAssembler.kt` (548 строк)

**Назначение:** Сборка боевых действий для Combat Sheet.

**Обрабатывает:**
- Оружие (weapon attacks с модификаторами)
- Заклинания (cantrips, spells с scaling)
- Фичи ( ADD_ACTION, SCALING_ACTION, MODIFIER_STACK)
- Rider Effects (дополнительные эффекты)
- Familiar Attacks (атаки фамильяров)
- Wild Shape (трансформации)

**Типы CombatAction:**
- `WEAPON` - атака оружием
- `CANTRIP` - заговор
- `SPELL` - заклинание
- `ITEM` - действие предмета
- `FEATURE_TOGGLE` - переключаемая фича

### MagicRegistryAssembler
**Файл:** `domain/usecase/snapshot/MagicRegistryAssembler.kt` (494 строк)

**Назначение:** Сборка магической системы персонажа.

**Обрабатывает:**
- Class Sources (волшебник, жрец, etc.)
- Race Sources (inherent magic)
- Item Sources (магические предметы)
- Feature Sources (embedded spells)
- Global Slots (слоты заклинаний)
- Pact Magic (чернокнижник)
- Spell Overrides (force_ritual, is_always_prepared)

## PYTHON ETL PIPELINE

### upgrade_JSON.py (544 строки)
**Путь:** `app/src/main/assets/database/DB/srd_data/upgrade_JSON.py`

**Архитектура:**
```
SRDImporter
├── setup()                    # Создание БД из схемы
├── transactional_load()       # Транзакционная загрузка
├── process_generic()          # Универсальный процессор
├── process_features()         # Features с FK normalization
├── process_spells()           # Spells с concentration/ritual
├── process_equipment()        # Weapons/Armor/Equipment
├── process_progression()      # Class Levels
├── process_conditions()       # Conditions с mechanics_json
└── process_monsters()         # Monsters с Actions/Effects
```

**Таблицы схемы (dnd_schema.sql):**
- **Reference:** equipment, weapons, armor, magic_items, spells, classes, subclasses, progression, features, races, subraces, backgrounds
- **Dictionaries:** damage_types, magic_schools, weapon_properties, proficiencies, skills, languages, alignments
- **Monster Engine:** monsters, monster_actions, monster_action_effects, monster_attack_patterns, monster_containers
